# 第 7 步：测试与验收

## 1. 验证层次与当前状态

当前只完成设计文档，所有下表中的业务测试均**待实现、待执行**。文档检查不能代替 API/数据库/前端测试，不能把预期结果写作已通过结果。

| 层次 | 工具/环境 | 核心证据 |
|---|---|---|
| 后端单元 | JUnit、固定 Clock、可阻塞/可失败阶段处理器 | 调用顺序、失败后未调用下一处理器、幂等逻辑 |
| 后端集成 | Spring Boot Test + MySQL 8.4 Testcontainers + 临时文件目录 | 真事务、约束、用户隔离、文件读写 |
| 前端组件/调度 | Vitest、Testing Library、受控 fetch、fake timers | 多任务、终态停查、旧响应、清理与查询异常 |
| API 联调 | 同源 Next.js→Java→MySQL | Cookie、CSRF、multipart、二进制、真实响应契约 |
| 手工端到端 | 浏览器、两个独立会话、Compose | AT-01～AT-14、键盘、小屏、刷新 |
| 可选增强 | Playwright | 自动化关键浏览器流程；非原题强制 |

Testcontainers 需要 Docker daemon；CI 的测试环境必须提供，缺少环境应明确失败，不能静默跳过集成测试后宣称完整通过。

## 2. 后端关键自动化用例

| ID | 场景 | 安排与断言 |
|---|---|---|
| BE-01 | 成功顺序 | spy 断言 VALIDATE→GENERATE→FINALIZE；真 DB 验证最终三成功、resultUrl 可读 |
| BE-02 | 指定阶段失败 | 参数化三个阶段；失败阶段 FAILED，前序成功，后序 SKIPPED；验证后续处理器调用次数为 0 |
| BE-03 | 阶段边界持久化 | 用闩锁暂停各阶段，在另一连接 GET/SELECT 验证已提交 RUNNING 与 currentStep/version；释放后继续 |
| BE-04 | 创建与执行解耦 | 让 GENERATE 阻塞在闩锁；断言 POST 已返回 taskId，随后释放闩锁并完成；禁止靠“sleep 大概够长”判断 |
| BE-05 | 创建事务回滚 | 在阶段/关联插入时注入 DB 异常；断言没有半条任务、没有 Worker 投递 |
| BE-06 | 所有权隔离 | A 上传/创建，B 读取素材/任务/结果均 404；B 提交 A 的 assetId 被拒且不建档 |
| BE-07 | 幂等并发 | 同用户同键并发相同请求只建一个任务、投递一次；异内容 409；不同用户同键可各建一项 |
| BE-08 | 队列拒绝 | 注入拒绝的执行器，不等待填满真实队列；任务 FAILED/EXECUTOR_REJECTED，三 SKIPPED，202 可查 |
| BE-09 | 文件校验 | 0 字节、非法 MIME、伪装图片、损坏文件、边界大小、宽高/像素上限；无可用素材行泄漏 |
| BE-10 | 模板二次校验 | 少/多素材、重复 ID、不满足模板类型大小、下架模板；返回明确错误 |
| BE-11 | GET 无副作用 | Worker 暂停时连续查询，对比状态/版本/updatedAt 不变；不能因请求次数推进阶段 |
| BE-12 | 终态与一致快照 | 旧 Worker 回调不能覆盖终态；并发交接下详情不出现 task/steps 跨版本组合 |
| BE-13 | 重启收敛 | 预置旧 QUEUED/RUNNING/终态；启动后分别失败收敛/保持终态，未执行阶段无开始时间 |
| BE-14 | 文件/DB 跨资源故障 | 移动失败不成功；提交结果不确定时先确认 DB，不误删成功文件；成功文件丢失 GET=503 且状态不变 |
| BE-15 | CSRF/会话 | 无/坏 token 的 POST 被拒；登录后旧 token 不可用；退出后访问 401；Cookie 属性符合配置 |
| BE-16 | 分页与筛选 | 同毫秒多个 ID 稳定排序、游标无重复遗漏、当前用户过滤、坏游标 400、ACTIVE 只含非终态 |

集成测试使用与设计一致的迁移和种子；断言六张表结构、复合外键和 CHECK 在 MySQL 上有效。异常测试清理本次独立目录/数据库，不依赖用户本机已有数据。

## 3. 前端关键自动化用例

| ID | 场景 | 断言 |
|---|---|---|
| FE-01 | 多任务乱序响应 | A/B/C 分别返回且顺序打乱，状态只更新对应 taskId；低 version 被丢弃 |
| FE-02 | 终态停查 | 收到 SUCCEEDED/FAILED 后推进 fake timers，不再发该 ID 自动请求 |
| FE-03 | 网络查询失败 | 保留原 RUNNING/阶段，queryError 有值；恢复后以新服务端版本同步 |
| FE-04 | 卸载/切页 | controller 已取消，timer/队列/监听已清理；迟到响应不回写 |
| FE-05 | 身份切换 | A 的延迟响应在 B 登录后到达，不出现在 B 页面，旧结果图立即卸载 |
| FE-06 | 上传替换/移除 | 旧 revision 响应被忽略，未 ready 不能提交，object URL 正确释放 |
| FE-07 | 提交结果不确定 | 网络超时后保留冻结请求与原幂等键；确认操作不产生新键 |
| FE-08 | 刷新/非首页进行中 | 历史第一页只有终态时，ACTIVE 分页仍发现更早任务并跟踪 |
| FE-09 | 轮询调度 | 同 ID 不重叠、全局最多 4 请求；退避/隐藏/恢复行为符合设计 |
| FE-10 | 跨标签/会话失效 | 身份事件或 401 清理所有个人数据；403 不伪造任务失败 |
| FE-11 | 基础可操作 | 标签、禁用、错误提示及键盘焦点合理；无效模板有返回入口 |

前端最低必验 FE-01～FE-05（对应 PRD §10.2），其余保障本次新增工程决策。测试只验证可观察行为，不把实现细节的函数调用顺序作为唯一断言。

## 5. 持久化与故障演示

在受控测试环境用绑定参数查询，不修改业务状态：

```sql
SELECT id, user_id, status, current_step, version, error_code, result_key,
       created_at, updated_at, started_at, finished_at
FROM generation_tasks WHERE id = :taskId;

SELECT step_name, step_order, status, started_at, finished_at, error_code
FROM task_steps WHERE task_id = :taskId ORDER BY step_order;
```

通过浏览器离开/刷新验证“客户端不影响 Java”；通过保持文件与数据库 volume 的容器重建验证历史保留。重启期间的旧任务按 SERVER_RESTARTED 失败属于本次明示边界，不应误验成“应继续生成”。不得用删 volume 测试普通重启，否则数据丢失不对应设计行为。
